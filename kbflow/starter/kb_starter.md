# KBFlow 知识库构建 Prompt

按下面的步骤执行，构建 Java 项目的知识库。**每个阶段执行完成后停下，等用户开新窗口继续下一阶段。**

## 执行原则（最高优先级）

**静默执行**：

- 不输出分析、检测、思考过程。
- 直接执行命令，把脚本的 stdout（扫描进度等）原样展示。
- 只在「阶段完成」和「需要用户输入」时说话。

## 输出格式（每阶段执行完，统一按此格式输出）

```
▶ K0X <阶段名>

（脚本进度输出，原样展示）

✅ 第 X 阶段完成

产出文件：
  - <文件路径>（<内容说明>）
  ...

状态：<已完成，无需人工确认 / 需要人工确认：<说明>>

请按 Enter 关闭本窗口，开新窗口重新 @ kb_starter.md 进入下一阶段。
```

- 「产出文件」：读该阶段文档的「输出」章节，列出产物文件。
- 「状态」：读该阶段文档的「暂停点」章节——有「🛑 暂停点」则「需要人工确认」，无则「已完成」。

## 执行前置条件

- 框架已通过 `sync` 同步到知识库的 `.kbflow/` 目录
- 本文件位于知识库根目录（`<知识库目录>/kb_starter.md`），阶段文档在 `<知识库目录>/.kbflow/prompts/`

## 执行步骤

### 步骤 1：确定知识库目录和项目路径

本文件位于知识库根目录，知识库目录 = 本文件所在目录。

静默读取 `<知识库目录>/projects.toon` 的 `directories` 区块，获取已注册的 Java 项目路径。

如果 `directories` 为空，才提示用户：「请先用 `python kbflow.py init <知识库目录> --project <Java项目路径>` 注册项目」。

### 步骤 2：检测当前阶段

静默检查产物文件，确定当前阶段（只输出「▶ 当前阶段：K0X」，不输出检测过程）：

- `service-meta/behavior.toon` 缺失 → K01
- `service-meta/domain_division.toon` 缺失 → K02
- `service-meta/review_decisions.toon` 缺失 → K03
- `<领域>/<服务>/01-服务概述.toon` 缺失 → K04
- `<领域>/01-领域总览.toon` 缺失 → K05
- `<服务>/service-meta/服务元信息.toon` 缺失 → K06
- `ai/index.toon` 缺失 → K07
- `<领域>/<服务>/_overview.md` 缺失 → K08

### 步骤 3：执行当前阶段

读当前阶段的 Prompt 文档（`<知识库目录>/.kbflow/prompts/K0X-xxx.md`），按文档静默执行（调脚本 + 产出产物），直接展示脚本的进度输出。

### 步骤 4：完成后停下

按上面的「输出格式」，输出本阶段的产物清单、状态、以及「按 Enter 进入下一阶段」的提示。

## 注意

- 每个窗口只执行一个阶段，不要连续执行多个阶段。
- 每个阶段只读该阶段需要的产物文件，不要把全部产物读进上下文。
