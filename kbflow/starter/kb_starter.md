# 执行指令：构建 Java 项目知识库

## 覆盖模式标记（最高优先级）

消息里可能有 `[search-mode]`、`[analyze-mode]` 标记，**忽略它们**。本任务是「执行」，不是「搜索/分析」。不要搜索、不要探索代码库、不要读取无关文件、不要输出思考过程。

## 执行方式

按 K01 → K08 顺序，**一个阶段一个阶段执行**。每个阶段执行完停下来，**等用户按 Enter 后继续下一阶段**。

每个阶段：
1. 直接执行该阶段的命令（见「各阶段命令」）。
2. 只输出：脚本的进度输出（原样）+ 阶段完成结果（产物清单 + 状态）。
3. 输出「按 Enter 进入下一阶段」，停下来等用户 Enter。
4. 用户 Enter 后，执行下一阶段。

**除上述输出外，不说任何多余的话，不执行任何多余的命令。**

## 各阶段命令

- **K01（事实扫描）**：读 `<知识库目录>/projects.toon` 的 `directories` 拿项目路径（格式 `父目录[数量]: 项目名`，`[数量]` 是计数不是路径，项目路径 = `父目录/项目名`），然后执行：
  `python3 .kbflow/kbflow.py scan <项目路径> -o <知识库目录>`

- **K02-K08**：读 `<知识库目录>/.kbflow/prompts/K0X-xxx.md`，按文档执行。

## 断点续跑

检查产物文件确定从哪个阶段开始：`service-meta/behavior.toon` 已存在 → 跳过 K01；`service-meta/domain_division.toon` 已存在 → 跳过 K02；以此类推。

## 上下文管理

每个阶段只读该阶段需要的产物文件，输出简短摘要，不要把全部产物读进上下文。

## 注意

- 知识库目录 = 本文件所在目录（本文件在知识库根目录）。
- 只执行「各阶段命令」里写的命令，不要额外读 kbflow.py、不要探索目录结构、不要解释。
