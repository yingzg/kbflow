# KBFlow 启动文档

这是 KBFlow 的**启动入口**。从这里开始：了解流程怎么走，然后按阶段清单逐阶段开新窗口执行。

本目录的 `K01`~`K08` 是各阶段的执行文档，供 AI IDE（opencode / codex / claude code）逐阶段执行。

## 分工边界

- **脚本做事实**：扫描器提取类名、注释、方法、表结构、依赖关系——确定的，脚本一次跑完。
- **AI 做语义**：把入口聚类成领域、给入口评分、补写服务概述——需要理解，由 AI 完成。

## 读写约定

- **读**：直接读 `.toon` 文件（紧凑格式，省 token）。
- **写**：AI 输出 **json**，用 `json2toon` 命令转 toon 落盘（不要手写 toon）。

## 上下文隔离（核心机制）

**每个阶段开一个新窗口执行**，不要在一个窗口串多个阶段：

- 阶段间靠**产物文件交接**（上一阶段产物落在 `<输出目录>/service-meta/` 或领域目录，下一阶段读文件）
- 每个窗口只跑一个阶段，上下文短、不溢出
- 一个阶段跑完，按 enter（关闭窗口），开新窗口 @ 下一阶段

这正是「阶段化」的意义：AI 上下文有限，串 8 阶段会溢出，必须每阶段独立窗口。

## 用法

在 AI IDE 里，**每个阶段开一个新窗口**，`@` 该阶段的 md 文档：

```bash
# 窗口 1：@kbflow/prompts/K01-事实扫描.md  → 执行 scan → 关窗口
# 窗口 2：@kbflow/prompts/K02-领域划分.md  → 读 K01 产物 → 聚类 → 关窗口
# ... 每个阶段一个窗口，直到 K08
```

断点续跑：某阶段产物已存在则跳过，从断点阶段继续。
