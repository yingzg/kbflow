# KBFlow 启动文档

你现在是 KBFlow 的构建执行者。目标：把一个 Java 项目转成结构化领域知识库。

## 执行方式

1. **先问用户**「项目路径 + 输出目录」（如果还没提供）。
2. **检测断点**：检查知识库目录的产物文件，确定「当前应该执行哪个阶段」。
3. **执行当前阶段**：读该阶段的文档（`K01-事实扫描.md` 等），按文档执行。
4. **阶段完成后停下来**：输出「✅ 第 X 阶段完成」，提示用户「按 Enter 关闭窗口，开新窗口重新 @ 本启动文档继续下一阶段」。

**不要一口气执行多个阶段**——每个窗口只执行一个阶段，避免上下文溢出。

## 阶段顺序与断点检测

按顺序检查产物文件，第一个不存在的产物对应「当前阶段」：

| 阶段 | 文档 | 断点检测（产物不存在 → 执行该阶段） |
|---|---|---|
| K01 | `K01-事实扫描.md` | `<输出目录>/service-meta/behavior.toon` |
| K02 | `K02-领域划分.md` | `<输出目录>/service-meta/domain_division.toon` |
| K03 | `K03-边界确认.md` | `<输出目录>/service-meta/review_decisions.toon` |
| K04 | `K04-领域知识.md` | `<输出目录>/<领域>/<服务>/01-服务概述.toon` |
| K05 | `K05-跨服务链路.md` | `<输出目录>/<领域>/01-领域总览.toon` |
| K06 | `K06-服务元信息.md` | `<输出目录>/<服务>/service-meta/服务元信息.toon` |
| K07 | `K07-全局导航.md` | `<输出目录>/ai/index.toon` |
| K08 | `K08-可读性交付.md` | `<输出目录>/<领域>/<服务>/_overview.md` |

## 开始

问清「项目路径 + 输出目录」后，检测断点，执行当前阶段。
