# K04 领域知识

## 目标

为每个领域生成 3 份文档：服务概述、接口链路、数据模型。先由脚本生成骨架（语义字段留 `[待AI补充]`），再由 AI 补语义。

## 读什么

- `<输出目录>/service-meta/` 下的 behavior / topology / ddl / mapper_tables / domain_division

## 步骤（对每个领域 × 每个服务循环）

### 第 1 步：生成骨架（脚本，3 条命令）

```bash
python kbflow.py skeleton overview --domain <领域名> --service <服务名> -o <输出目录>
python kbflow.py skeleton interface --domain <领域名> --service <服务名> -o <输出目录>
python kbflow.py skeleton data-model --domain <领域名> --service <服务名> -o <输出目录>
```

脚本按领域过滤入口、做表映射 BFS，产出带 `[待AI补充]` 占位的骨架。

### 第 2 步：补服务概述语义（AI）

读 `01-服务概述.toon`，补全 `[待AI补充]` 字段：
- `service_info.description`：一句话服务定位
- `service_info.core_responsibilities`：3-5 条核心职责
- 每个场景的 `name`（语义名）和 `desc`（一句话描述）

只补语义，不改入口清单、优先级、ID。输出 json（含 `description`、`core_responsibilities`、`scenarios`），用 json2toon 覆盖回 `01-服务概述.toon`。

```bash
python kbflow.py json2toon --json-file 概述.json --out <输出目录>/<领域>/<服务>/01-服务概述.toon
```

### 第 3 步：接口链路 + 数据模型（大多确定性，AI 仅在需要时补语义）

`02-接口链路.toon` 和 `03-数据模型.toon` 由脚本生成，表映射已确定性完成。若个别字段（如外部依赖的业务含义）需要解释，AI 补充。

## 输出

`<输出目录>/<领域>/<服务>/01-服务概述.toon`、`02-接口链路.toon`、`03-数据模型.toon`

## 门禁

每份文档无 `[待AI补充]` 残留（服务概述的语义字段必须补全）。
