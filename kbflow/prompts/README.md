# KBFlow — AI 驱动构建指南

KBFlow 把一个 Java 微服务代码库，转成结构化的领域知识库。它不是一条命令跑到底，而是**分阶段推进**，每个阶段由「确定性脚本」和「AI 语义理解」分工完成。

## 分工边界（核心约定）

- **脚本做事实**：扫描器提取类名、注释、方法、表结构、依赖关系——这些是确定的，脚本一次跑完。
- **AI 做语义**：把入口聚类成领域、给入口评分、补写服务概述——这些需要理解，由你（AI）完成。

## 读写约定（省 token + 防错）

- **读**：直接读 `.toon` 文件。toon 是紧凑格式（`表[行数]{列}: 值,值`），比 json 省大量 token。
- **写**：你输出 **json**，用 `json2toon` 命令转成 toon 落盘。不要手写 toon（容易写错）。

## 统一约定

- 产物目录：`<output>/service-meta/`（事实层）、`<output>/<领域>/<服务>/`（知识层）
- 断点续跑：某个阶段产物已存在 → 跳过该阶段
- 人工介入点：只有「领域清单确认」和「低置信度复核」两处需要等人，其余自动推进

## 阶段总览

| 阶段 | 名称 | 谁做语义 |
|---|---|---|
| K01 | 事实扫描 | 无（纯脚本） |
| K02 | 领域划分 | AI 聚类 + 分类 |
| K03 | 边界确认 | AI 四维评分 |
| K04 | 领域知识 | AI 补服务概述 |
| K05 | 跨服务链路 | AI 补领域总览 |
| K06 | 服务元信息 | AI 补服务定位 |
| K07 | 全局导航 | AI 汇总索引 |
| K08 | 可读性交付 | AI 写叙述 + 术语表 |

## 主流程与 skill

每个阶段的主 md 文档只做「编排」：读什么 → 调什么脚本 → 调什么 skill → 门禁 → 暂停点。

「AI 语义」的具体实现放在 `skill-*.md` 子文档里（如 `K02-领域划分/skill-01-领域聚类.md`）。

修改 KBFlow 时，通常只改 md 流程：

- 改流程顺序 / 门禁 / 暂停点 → 改主 md
- 改某个 AI 语义的具体做法（prompt、输出格式）→ 改对应 skill md
- 只有事实提取逻辑要变时，才改脚本（scanners / tools）

## 用法

在 AI IDE（opencode / codex / claude code）里，`@` 引用对应阶段的 md 文档，按文档执行。逐阶段推进，每阶段完成后看下一个。

```bash
python kbflow.py scan examples/demo-java -o kb   # K01
# 然后 @kbflow/prompts/K02-领域划分.md
```
