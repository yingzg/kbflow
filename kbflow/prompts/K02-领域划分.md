# K02 领域划分

## 目标

把 K01 扫描出的业务入口，聚类成「限界上下文」级别的业务领域，并把每个入口归属到某个领域。

## 读什么

- `<输出目录>/service-meta/behavior.toon`

## 流程

### 1. 调 skill-01 聚类领域

打开 `K02-领域划分/skill-01-领域聚类.md`，按它聚类出领域建议，产出 `domain_suggestion.toon`。

### 2. 生成边界矩阵（脚本）

```bash
python3 .kbflow/kbflow.py matrix --domains <输出目录>/service-meta/domain_suggestion.toon --out <输出目录>/service-meta/domain_boundary_matrix.toon
```

matrix 命令读 `domain_suggestion.toon` 的 `domains` 字段（每个领域有 `name`/`responsibility`/`key_entities`/`boundary_included`/`boundary_excluded`，多值字段是 `|` 拼接的字符串），生成 `domain_boundary_matrix`（每个领域加 `id`：D1/D2…）。不用手动改字段格式，命令自动处理。

### 🛑 3. 人工确认领域清单

打开 `<输出目录>/service-meta/domain_suggestion.toon`，让用户检查修改（改领域名、增删领域）。改完后继续。

### 4. 调 skill-02 分类入口

打开 `K02-领域划分/skill-02-入口分类.md`，按它把每个入口分类到领域，产出 `domain_mapping.toon`。

### 5. 合并成领域划分

把边界矩阵（`domain_boundary_matrix`）和入口分类（`domain_mapping`）合并成 `domain_division.toon`：

1. 读 `domain_boundary_matrix.toon` 的 `domain_boundary_matrix`（每个领域有 `id`=D1/D2 和 `name`）
2. 读 `domain_mapping.toon` 的 `domain_mapping`（每个入口有 `entry_id` 和 `domain`=领域名）
3. 把每个入口的 `domain`（领域名）转成 `domain_ref`（D1/D2，查 `name`→`id` 映射；查不到的填 `D99`）
4. 写 `domain_division.json`，用 json2toon 落盘：

```bash
python3 .kbflow/kbflow.py json2toon --json-file domain_division.json --out <输出目录>/service-meta/domain_division.toon
```

`domain_division.json` 结构：

```json
{"domain_boundary_matrix":[{"id":"D1","name":"库存",...}],"domain_mapping":[{"entry_id":"API-001","domain_ref":"D1","reason":"..."}]}
```

## 输出

`<输出目录>/service-meta/domain_division.toon`

## 门禁

每个 K01 入口都必须有 `domain_ref`（无则填 `D99`），入口数守恒。
