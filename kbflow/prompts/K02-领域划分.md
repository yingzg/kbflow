# K02 领域划分

## 目标

把 K01 扫描出的业务入口，聚类成「限界上下文」级别的业务领域，并把每个入口归属到某个领域。

## 读什么

- `<输出目录>/service-meta/behavior.toon`（直接读，注意每个入口的 `class_name` / `package` / `doc` / `methods`）

## 步骤

### 第 1 步：聚类领域（AI 语义）

读 behavior.toon 的全部入口，把它们聚类成 5-8 个业务领域（限界上下文级别）。约束：

1. 领域是「一组内聚的业务能力」，不要切成过细的功能模块。
2. 技术性通用能力（枚举、字典、文件上传下载、日志、权限）归入「公共支撑」领域。
3. 纯查询/工作台/汇总统计类入口，归入其所属业务域，不单独成领域。

每个领域输出：领域名、一句话职责、核心实体、边界内能力、边界外能力。

输出 json 数组，写文件：

```bash
python kbflow.py json2toon --json-file 领域建议.json --out <输出目录>/service-meta/domain_suggestion.toon --wrap domains
```

json 结构（`--wrap domains` 后为 `{"domains": [...]}`）。注意：多值字段用 `|` 拼接成字符串，不要用数组（toon 不支持嵌套数组）：

```json
[{"name":"库存","responsibility":"库存查询与扣减","key_entities":"库存|库存记录","boundary_included":"库存查询|扣减","boundary_excluded":"调拨"}]
```

### 第 2 步：生成边界矩阵（脚本）

```bash
python kbflow.py matrix --domains <输出目录>/service-meta/domain_suggestion.toon --out <输出目录>/service-meta/domain_boundary_matrix.toon
```

### 🛑 第 3 步：人工确认领域清单

打开 `<输出目录>/service-meta/domain_suggestion.toon`，让用户检查修改（改领域名、增删领域）。改完后继续。

### 第 4 步：分类入口（AI 语义）

读修改后的领域清单 + behavior.toon 全部入口，把每个入口分类到最合适的领域。无法确定的标记 `unclassified`（宁可拒识，不要误识）。

每个入口输出：`entry_id`、`domain`（领域名）、`reason`（类名:业务动作→领域）。

输出 json 数组：

```bash
python kbflow.py json2toon --json-file 入口分类.json --out <输出目录>/service-meta/domain_mapping.toon --wrap domain_mapping
```

### 第 5 步：合并成领域划分（AI 拼装）

把边界矩阵（`domain_boundary_matrix`）和入口分类（`domain_mapping`）合并，entry 的 `domain` 转成 `domain_ref`（D1/D2…），写 `domain_division.toon`。

```bash
python kbflow.py json2toon --json-file domain_division.json --out <输出目录>/service-meta/domain_division.toon
```

`domain_division.json` 结构：

```json
{"domain_boundary_matrix":[{"id":"D1","name":"库存",...}],"domain_mapping":[{"entry_id":"API-001","domain_ref":"D1","reason":"..."}]}
```

## 输出

`<输出目录>/service-meta/domain_division.toon`（含边界矩阵 + 入口归属）

## 门禁

每个 K01 入口都必须有 `domain_ref`（无则填 `D99`），入口数守恒。
